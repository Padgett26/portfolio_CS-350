# portfolio_CS-350
Portfolio for SNHU CS-350

## Summarize the project and what problem it was solving.
This project was to build a thermostat embedded system that accepted user inputs for changing the off/heat/cool state, and setting the set temperature, the goal room temp.

## What did you do particularly well?
The code is clean and performs all of the required function.

## Where could you improve?
I could add more filtering of user interrupts. I noticed that if I push the state change button too slowly, the state would change twice.

## What tools and/or resources are you adding to your support network?
Many of the tools, hardware and software, were new to me, and I can see myself utilizing these tools in future, similar, projects.

## What skills from this project will be particularly transferable to other projects and/or course work?
The primary skill I will be able to use in future is the understanding of how embedded systems are built, controlled, and communicate within its own system and with larger systems, of which it a part of. When writing software, I hadn't really thought of embedded systems, but now I have a better understanding, and I now know that embedded type systems are an option.

## How did you make this project maintainable, readable, and adaptable?
Breaking the code into specific functional elements allows the code to remain organized, and easier to transverse. Specific functional elements are isolated and can be maintained, debugged, nd tweaked without affecting other elements. Since each element is isolated, it could utilized in other projects as a plug in. Commenting increases the readability and clarifies code element purpose and functionality.
